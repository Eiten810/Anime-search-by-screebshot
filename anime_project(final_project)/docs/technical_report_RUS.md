# Технический отчет

## Поиск аниме по скриншоту

### Обзор проекта

Целью проекта является разработка системы поиска аниме по загруженному пользователем изображению (скриншоту).

В отличие от задачи классификации изображений, система использует подход **Image Retrieval**. Вместо прямого определения класса изображение преобразуется в вектор признаков (эмбеддинг), который затем сравнивается с эмбеддингами изображений из базы данных. Наиболее похожие изображения определяются с использованием косинусного сходства.

В рамках проекта были реализованы и сравнены несколько подходов к извлечению эмбеддингов для определения наиболее эффективной модели.

---

# Датасет

Для проекта был сформирован собственный датасет.

Первоначально использовался готовый набор изображений, однако после его анализа было обнаружено большое количество нерелевантных и низкокачественных изображений. После очистки объем данных оказался недостаточным для обучения моделей.

Для решения этой проблемы был разработан скрипт автоматического извлечения кадров непосредственно из серий аниме, что позволило сформировать новый датасет из качественных скриншотов.

Итоговый датасет содержит **24 009 изображений**, относящихся к **23 различным аниме**.

Датасет был разделен на три части:

- обучающая выборка — 70%;
- валидационная выборка — 15%;
- тестовая выборка — 15%.

Тестовая выборка не использовалась при обучении моделей и формировании поисковой базы, что исключает утечку данных во время оценки качества.

---

# Извлечение эмбеддингов

В ходе работы были реализованы и сравнены четыре различных подхода.

## Gemini Embedding 2 (Original)

Изображения передаются модели Gemini Embedding 2 в исходном разрешении без предварительного изменения размера.

---

## Gemini Embedding 2 (512×512)

Перед извлечением эмбеддингов изображения масштабируются до размера **512×512**, что позволяет оценить влияние разрешения изображения на качество поиска.

---

## ResNet50 (Classification)

Модель ResNet50 обучается как классификатор на обучающей выборке.

После завершения обучения классификационная голова удаляется, а оставшаяся часть сети используется как экстрактор признаков для получения эмбеддингов изображений.

Размер входного изображения:

- **224×224**

---

## ResNet50 (Triplet Loss)

Для повышения качества поиска была разработана дополнительная модель, обучаемая с использованием функции потерь **Triplet Loss**.

В отличие от классификации, данная модель обучается формировать пространство признаков, в котором изображения одного аниме располагаются ближе друг к другу, а изображения разных аниме — дальше друг от друга.

---

# Алгоритм поиска

Процесс поиска состоит из следующих этапов:

1. Пользователь загружает изображение.
2. Для изображения вычисляется эмбеддинг.
3. Полученный эмбеддинг сравнивается с базой эмбеддингов при помощи косинусного сходства (Cosine Similarity).
4. Все изображения сортируются по степени сходства.
5. Пользователю отображаются **5 наиболее похожих результатов**.

---

# Методика оценки

Для объективного сравнения моделей использовалась отдельная схема оценки качества.

База поиска формировалась **только из эмбеддингов обучающей выборки**.

В качестве запросов использовались **только изображения тестовой выборки**.

Таким образом, ни одно тестовое изображение не присутствовало в поисковой базе, что позволило исключить утечку данных и получить объективные результаты.

## Формирование поисковой базы

В ходе разработки была изменена организация базы эмбеддингов для проведения корректной оценки моделей.

Первоначально поисковая база содержала эмбеддинги всех изображений датасета. Такой подход приводил к тому, что изображения тестовой выборки одновременно использовались и в качестве запросов, и присутствовали в поисковой базе, что могло приводить к завышению значений Retrieval-метрик.

Для устранения данной проблемы структура проекта была изменена.

В результате были сформированы две независимые базы эмбеддингов:

- **Полная база** — содержит эмбеддинги всех изображений датасета и используется при поиске изображений, загруженных пользователем.
- **Обучающая база** — содержит эмбеддинги только обучающей выборки и используется исключительно при вычислении Retrieval-метрик.

Во время оценки качества запросами выступают изображения тестовой выборки, которые сравниваются только с эмбеддингами обучающей базы.

Таким образом обеспечивается отсутствие пересечения между тестовыми изображениями и поисковой базой, что позволяет получить объективную оценку качества моделей.

# Решенные проблемы

В процессе разработки было принято несколько важных архитектурных решений.

## Формирование собственного датасета

После очистки первоначального датасета количество изображений значительно сократилось. Для увеличения объема данных был разработан скрипт автоматического извлечения кадров из видеофайлов аниме, что позволило сформировать новый датасет.

## Использование различных размеров изображений

Изначально все изображения приводились к размеру **224×224**.

Позже было принято решение использовать разные стратегии предварительной обработки:

- **Gemini Original** — изображения в исходном разрешении;
- **Gemini 512** — изображения размером 512×512;
- **ResNet50** — изображения размером 224×224.

Это позволило корректно сравнить различные модели извлечения эмбеддингов.

## Использование Triplet Loss

Во время разработки стало очевидно, что модель ResNet50, обученная исключительно как классификатор, не обеспечивает максимально возможного качества поиска похожих изображений.

В связи с этим была реализована дополнительная модель на основе **Triplet Loss**, предназначенная непосредственно для обучения пространства эмбеддингов.
